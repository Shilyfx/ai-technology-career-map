# Vault Design

## 目录职责

| 目录 | 作用 |
| --- | --- |
| `00-Home` | 入口、地图、路线与当前技术雷达 |
| `01-Inbox` | 陌生名词和待分类材料 |
| `02-Foundations` | 数据、数学、软件、ML 闭环 |
| `03-Models` | 模型、训练与多模态能力 |
| `04-Applications` | RAG、Agent、eval、产品工程 |
| `05-Systems` | 数据系统、MLOps、Infra、推理 |
| `06-Safety` | 安全、安全工程、治理 |
| `07-Careers` | 岗位、技能矩阵和作品证据 |
| `08-Paths` | 基于岗位的专修路线 |
| `90-Sources` | 可替换的市场快照与来源 |
| `99-Templates` | 新术语、技术、岗位笔记模板 |
| `99-System` | 本 Vault 的维护约定 |

## 链接原则

- 入口页指向 5–10 个高价值页面；
- 概念页链接前置、后续与相邻概念；
- 市场快照不承担稳定定义；
- 工具/框架名优先放在所属概念页，除非确实需要独立比较；
- 避免为了图谱好看而建立虚假关系。

## 更新优先级

1. 新问题先写入 Inbox；
2. 影响多个页面的定义先更新 Concept；
3. 当前技术或岗位变化只更新 Radar/Snapshot；
4. 被多个页面重复引用的条目再升级为独立笔记；
5. 每季度审核来源、失效链接、过时的“当前”说法。
